# Устройство публичного API

[English](../public-api.md) | Русский | [简体中文](../zh/public-api.md)

> Тип: проектное решение. Этот документ фиксирует границы и решения о
> стабильности Node.js-клиента Arrow Flight.

Карта точек входа пакета определяется в [`package.json`](../../package.json).
Корневая поверхность исходного кода и отобранное пространство имён
низкоуровневого протокола определяются в
[`src/index.ts`](https://github.com/woodger/arrow-flight-client/blob/v0.0.14/src/index.ts)
и
[`src/flight-protocol.ts`](https://github.com/woodger/arrow-flight-client/blob/v0.0.14/src/flight-protocol.ts).
Наблюдаемое поведение потоков защищено тестами, расположенными рядом с кодом в
[`src/client/`](https://github.com/woodger/arrow-flight-client/tree/v0.0.14/src/client),
а контракт передачи данных остаётся в
[`contracts/Flight.proto`](../../contracts/Flight.proto).

## Граница API

Корень пакета предоставляет принадлежащие проекту дескрипторы, значения
метаданных, объекты ответов и объекты Arrow JS. Особенности сгенерированного
protobuf, такие как элементы перечислений, пустые поля `Buffer`, `dataHeader` и
`dataBody`, не входят в высокоуровневое соглашение о вызовах.

Низкоуровневые protobuf-контракты намеренно сгруппированы в пространстве имён
`flightProtocol`, а не добавлены в высокоуровневую поверхность как плоский
набор. Пространство имён экспортирует явный набор сообщений Flight, кодеков,
перечислений, определение сервиса и принадлежащий проекту тип `FlightRawClient`;
вспомогательные функции генератора и типы серверной реализации остаются
внутренними.

`FlightClient.raw` предоставляет этот низкоуровневый клиент на существующем
канале. Этот низкоуровневый доступ предназначен для операций Flight или
расширений приложения, у которых пока нет высокоуровневой обёртки.

Низкоуровневые вызовы намеренно сохраняют семантику транспортного уровня. Их
`FlightRawCallOptions` принимают `flightProtocol.RawMetadata`, отмену и
обработчики заголовков и трейлеров, но не применяют нормализацию `deadline` или
проверку закрытого клиента из фасада. `FlightServiceDefinition` остаётся
доступным для пользовательской сборки с совместимой прямой зависимостью
`nice-grpc`.

## Миграция низкоуровневого API

Прежние именованные импорты из `arrow-flight-client/raw` переносятся в корневое
пространство имён:

```ts
import { flightProtocol } from 'arrow-flight-client';

const message = flightProtocol.FlightData.create({ dataHeader, dataBody });
type RawClient = flightProtocol.FlightRawClient;
```

Для сгенерированных вложенных имён используются отобранные псевдонимы:

- `FlightDescriptor_DescriptorType` становится
  `flightProtocol.FlightDescriptorType`;
- `CloseSessionResult_Status` становится `flightProtocol.CloseSessionStatus`;
- `SessionOptionValue_StringListValue` становится
  `flightProtocol.SessionOptionStringListValue`;
- `SetSessionOptionsResult_Error` становится
  `flightProtocol.SetSessionOptionsError`;
- `SetSessionOptionsResult_ErrorValue` становится
  `flightProtocol.SetSessionOptionsErrorValue`.

Прежний псевдоним `FlightGrpcClient` и сгенерированный тип `FlightServiceClient`
становятся `flightProtocol.FlightRawClient`.
`flightProtocol.FlightProtocolInput<T>` предоставляет рекурсивную форму запроса,
которую принимают этот клиент и отобранные кодеки. Для вспомогательных функций
генератора и типов серверной реализации публичной замены нет.

`apache-arrow@^21.1.0` является обязательной peer-зависимостью. Приложение и
клиент должны разрешать один экземпляр библиотеки во время выполнения, поскольку
таблицы, объекты `RecordBatch`, схемы и IPC writers Arrow зависят от
runtime-идентичности классов. Значения из второй физической копии или
неподдерживаемой мажорной версии не являются совместимыми публичными входными
данными.

## Потоковая модель

Потоки ответов Flight остаются значениями `AsyncIterable`. `listFlights()`,
`doPut()`, `doAction()` и `listActions()` не накапливают ответы. `doGet()`
возвращает одноразовый `FlightStreamReader`, чтобы объект `RecordBatch` сохранял
связь со своими прикладными метаданными, а сообщения только с метаданными не
отбрасывались.

Накопление выполняется явно: `getTable()` создаёт полную Arrow `Table`, а
`putTable()` собирает все сообщения сервера `PutResult`.

## Ответственность за IPC

Клиент отвечает за преобразование между фреймингом Flight и Arrow IPC:

- каждый `FlightData.dataHeader` содержит один необработанный Arrow IPC `Message`
  flatbuffer;
- `FlightData.dataBody` содержит только соответствующие буферы тела Arrow;
- дескриптор `DoPut` прикрепляется только к первому сообщению;
- прикладные метаданные клиента отправляются отдельным сообщением только с
  метаданными сразу после схемы `DoPut`, чтобы серверные средства чтения могли
  увидеть их даже при отсутствии данных;
- поток `DoGet` восстанавливает инкапсулированный IPC-фрейминг до чтения схемы,
  сообщений словарей и объектов `RecordBatch` библиотекой Arrow JS;
- длина тела проверяется до передачи данных в средство чтения Arrow.

При использовании корня пакета вызывающий код не должен конструировать эти поля.
IPC-адаптер сохраняет заданные вызывающим кодом границы пакетов и не разбивает
слишком большой `RecordBatch` автоматически.

## Жизненный цикл и вызовы

`FlightClient` владеет одним gRPC-каналом. `close()` идемпотентен, а новые
высокоуровневые вызовы после закрытия отклоняются. Метаданные клиента применяются
к каждому вызову; метаданные отдельного вызова заменяют совпадающие настроенные
ключи, а пустой массив значений удаляет настроенный ключ для этого вызова.
Высокоуровневые вызовы поддерживают `AbortSignal` и абсолютный `deadline` типа
`Date`. Отмена вызывающим кодом отклоняет вызов с `AbortError`; истечение
`deadline` высокоуровневого вызова возвращает `ClientError` из `nice-grpc` с кодом
`DEADLINE_EXCEEDED`.

TLS по умолчанию использует системные корневые сертификаты и принимает
пользовательские корни вместе с необязательными идентификационными данными
mutual TLS. Приватный ключ и цепочка сертификатов образуют один набор
идентификационных данных и должны задаваться вместе.

`maxReceiveMessageLength` и `maxSendMessageLength` настраивают соответствующие
gRPC-ограничения размера сообщений в байтах. Ограничение применяется к каждому
сериализованному сообщению `FlightData`, а не ко всему потоку, поэтому большие
логические объёмы данных следует передавать в нескольких ограниченных объектах
`RecordBatch` с запасом на транспортную оболочку.

## Текущий объём

Высокоуровневый API охватывает обнаружение данных, `GetFlightInfo`,
`PollFlightInfo`, `GetSchema`, `DoGet`, `DoPut` и действия. Для `Handshake` и
`DoExchange` требуется `FlightClient.raw`; вызывающий код низкоуровневого
`DoExchange` также отвечает за фрейминг Arrow IPC. Автоматическая маршрутизация
по местоположениям endpoint не реализована. Транспортные сбои остаются ошибками
`nice-grpc`; истечение `deadline` явно сообщается статусом `DEADLINE_EXCEEDED`
для высокоуровневых вызовов.
